# CareDocLib 基本設計書

| 項目 | 内容 |
|---|---|
| 状態 | 改訂版（ADR-002 / ADR-003 / ADR-004 反映） |
| 対象 | Windows Tauri デスクトップアプリ |

本書は、CareDocLib の画面・構成・データ・認証認可の基本方針を示す。認証・操作者識別の詳細実装仕様は [09-auth.md](impl/09-auth.md)、バックアップ詳細仕様は [08-backup.md](impl/08-backup.md) で定める。

## 1. システム構成

- Windows 上で動作する Tauri デスクトップアプリとする。業務ロジック・PDF 生成・データ保存・認証認可は HTML / CSS / JavaScript に集約し、Rust は Tauri Runtime としてのみ利用する（[ADR-002](adr/ADR-002-indexeddb-storage.md)）。
- 利用者情報、共通設定、アカウント情報は端末内の IndexedDB（DB名 `caredoc`）に保存し、外部サーバーとの通信やリアルタイム同期は行わない。
- PDF 生成は既存の `pdf-lib` と申請書テンプレート（`public/data/`）を利用する。
- CSP（`tauri.conf.json`）および Tauri capabilities（`permissions: []`）の最小権限を維持する。
- 論理構成は次のとおりとする。

```text
View（index.html / admin.html / 認証オーバーレイ）
        ↓
Controller（main.js / admin.js / auth-ui.js）
        ↓
Service / Guard（認証・セッション・15分ロック・PDF生成・バックアップ）
        ↓
Model（storage-core / storage-crud / storage-seed / auth-store）
        ↓
IndexedDB（caredoc v2）
```

## 2. 利用者とアクセス範囲

| 利用者 | 基本設計上のアクセス範囲 |
|---|---|
| 担当者（1ロール共通） | 認証成功後、申請書PDF作成、利用者管理、共通設定、バックアップ書き出し・復元、アカウント管理のすべてを利用可能 |

- 未認証、または 15 分無操作ロック中は業務画面・データ操作へアクセスできない。
- 画面上の非表示だけに依存せず、データ操作・PDF 生成・バックアップの入口でも認証状態（セッション有効性）を確認する。
- アプリ内認証は OS 上のファイルアクセスを分離するものではなく、端末保護は Windows ログイン・BitLocker に委ねる（[ADR-003](adr/ADR-003-data-protection.md)）。

## 3. 画面構成

| 画面 | 主な機能 | 状態 |
|---|---|---|
| 初回セットアップ / ログイン / ロック | 最初のアカウント登録、ログイン・ログアウト、15分ロック解除 | 実装済（[09-auth.md](impl/09-auth.md)） |
| 申請書作成（`index.html`） | 利用者選択、申請情報入力、PDF 作成・プレビュー・保存、ヘッダーにログイン中ユーザー表示 | 現行画面を拡張 |
| 利用者管理（`admin.html`） | 利用者情報の登録・一覧・編集・削除・最終更新者表示 | 現行画面を拡張 |
| 共通設定（`admin.html`） | 共通設定の登録・編集 | 現行画面を利用 |
| バックアップ・復元（`admin.html`） | JSON 書き出し、検証、復元前自動バックアップ付き復元 | 実装済（[08-backup.md](impl/08-backup.md)） |
| アカウント管理（`admin.html`） | アカウント作成・表示名変更・PIN 変更/再設定・削除 | 実装済（[09-auth.md](impl/09-auth.md)） |

画面ごとの遷移や入力仕様は [画面設計書](screen-design.md) で定める。

## 4. 主要処理

### 4.1 認証・セッション・15分画面ロック

1. 起動時（`index.html` / `admin.html` 読み込み時）、業務データを読み込む前に IndexedDB 内のアカウント件数と `sessionStorage` のセッションを確認する。
2. アカウント 0 件なら初回セットアップを表示し、1 件以上かつ未認証ならログイン画面を表示する。
3. 認証成功後、ヘッダーにログイン中の担当者名を表示し、業務画面を表示する。
4. 最終操作から 15 分間経過（スリープ復帰含む）した場合、作業中のフォーム内容を保持したままロック画面を被せ、4 桁 PIN の再入力で解除する。

### 4.2 PDF作成

1. 登録済み利用者を選択する（または新規入力する）。
2. 情報を確認・修正し、申請日等を指定する。
3. 区分変更の場合のみ変更更新理由を入力する。
4. テンプレート、座標データ、共通設定と入力内容から PDF を生成する。
5. プレビューで確認し、問題なければダウンロード・印刷する。役所への提出はアプリの対象外とする。

### 4.3 バックアップと復元

- 担当者が利用者情報・共通設定を `caredoc-backup` v1 形式の JSON として手動書き出しする（アカウント情報や更新者メタデータは含めない）。
- 復元時はファイルサイズ・JSON 構文・形式・項目・利用者 0 件チェックを検証し、確認後に現在のデータを自動バックアップ（`before-restore`）してから全件置き換えを実行する。
- 復元されたデータには復元を実行したログインユーザーを更新者として記録する。

## 5. 論理データ（IndexedDB `caredoc` v2）

| ストア | 主な内容 | 備考 |
|---|---|---|
| `accounts` | `accountId`, `displayName`, `role` (`"staff"`), PBKDF2 ハッシュ・ソルト、失敗回数・ロック解除時刻 | PIN 平文を保存しない |
| `members` | 申請書作成に必要な利用者情報（`MEMBER_FIELDS`）＋作成者/更新者メタデータ | 全担当者で共有 |
| `settings` | 申請書に適用する共通設定（`SETTINGS_FIELDS`）＋作成者/更新者メタデータ | 1件（`id: "singleton"`） |

## 6. エラー・保護方針

- 認証失敗、保存失敗、PDF 生成失敗、バックアップ検証・復元失敗は画面に明示する。失敗を成功として扱わない。
- 保存データとバックアップの暗号化はアプリでは行わない（[ADR-003](adr/ADR-003-data-protection.md)）。
- コンソールログやエラー表示に個人情報および PIN を含めない。
- UI からデータベースへ直接アクセスせず、データ操作・PDF 生成の入口でセッション状態を確認する。
- バックアップ復元は検証と自動退避の後に 1 トランザクションで切り替え、失敗時に現行データを不整合な状態にしない。
