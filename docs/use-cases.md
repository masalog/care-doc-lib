# CareDocLib ユースケース

| 項目 | 内容 |
|---|---|
| 状態 | 改訂版（ADR-002 / ADR-003 / ADR-004 反映） |
| 対象 | Windows Tauri デスクトップ版（現行機能および追加開発対象） |

## アクター

- **担当者（1ロール共通権限）**：アカウントでログインし、利用者情報・共通設定の管理、申請書PDF作成、JSONバックアップ・復元、アカウント管理を行う。

> 本アプリは小規模事業所・個人PCでのデスクトップ運用を前提とし、ロールは 1 ロール（全アカウント共通権限）とする。操作者の識別と離席時等の誤操作・なりすまし防止を目的とする（[ADR-004](adr/ADR-004-authentication-authorization.md)）。

## UC-01 アプリにログイン・ロック解除する

- **アクター**：担当者
- **開始条件**：アプリを起動する（または 15 分無操作により画面がロックされる）。
- **基本フロー**：
  1. アカウントが未登録（0件）の場合、アプリは初回アカウント登録画面を表示し、最初のアカウントを作成する。
  2. アカウントが登録済みの場合、アプリはログイン画面を表示する。
  3. 担当者は自分のアカウントIDと 4 桁の数字 PIN を入力する。
  4. アプリは認証し、ログイン中ユーザーとして操作を許可する。
  5. 15分間操作がなければアプリをロックし、PIN 再入力（またはログアウトして別アカウントでログイン）を求める。
- **例外**：認証に失敗した場合はエラーを表示し、再入力を促す。連続 5 回失敗時は 1 時間の一時ロックを行う。

## UC-02 利用者情報を登録・更新・削除する

- **アクター**：担当者
- **開始条件**：ログイン済みかつ未ロックである。
- **基本フロー**：
  1. 利用者を選択する。未登録の場合は新規登録する。
  2. 情報を入力または修正する。
  3. 内容を確認し、保存する。
- **結果**：保存した利用者情報を端末内の担当者間で共有し、作成者・最終更新者（`createdBy` / `updatedBy` 等）と更新日時を記録する。
- **補足**：確認ダイアログを経て削除もできる。

## UC-03 共通設定を更新する

- **アクター**：担当者
- **開始条件**：ログイン済みかつ未ロックである。
- **基本フロー**：
  1. 共通設定を開く。
  2. 設定値を入力・修正し、保存する。
  3. 保存した設定は以降のPDF作成に適用され、最終更新者を記録する。

## UC-04 申請書を作成・提出する

- **アクター**：担当者
- **開始条件**：ログイン済みかつ未ロックであり、申請依頼を受けた、認定有効期間の終了が近い、または要介護状態が変化した。
- **基本フロー**：
  1. 利用者を選ぶ。未登録の場合は UC-02 で登録する。
  2. 申請に使う情報を確認し、必要があれば修正・保存する。
  3. 区分変更の場合のみ、申請理由を入力する。
  4. 申請日等を指定し、PDFを作成する。
  5. PDFをプレビューし、内容を確認する。
  6. 誤りがあれば利用者情報等を修正して再作成する。問題がなければダウンロード・印刷し、担当者が提出する。
- **補足**：申請のきっかけは記録・分類しない。申請区分の自動判別もしない。
- **範囲**：アプリの対象は PDF の作成・保存・印刷まで。役所への提出は担当者がアプリ外で行う。

## UC-05 アカウントを管理する

- **アクター**：担当者
- **開始条件**：ログイン済みかつ未ロックである。
- **基本フロー**：
  1. 担当者がアカウント管理画面を開く。
  2. 新規アカウントの作成、表示名の変更、PIN 変更・再設定、またはアカウントを削除する。
  3. 変更結果を確認する。
- **制約**：最後の 1 件のアカウントを削除する場合は現在の PIN 再入力を必須とする（削除後は利用者データを保持したまま初回登録画面に戻る）。PIN は平文で保存しない。

## UC-06 バックアップを書き出す

- **アクター**：担当者
- **開始条件**：ログイン済みかつ未ロックである。
- **基本フロー**：
  1. 担当者がバックアップ書き出しを実行する。
  2. アプリが利用者情報と共通設定を JSON ファイル（`caredoc-backup` v1 形式）として書き出す。
  3. 保存件数の結果を確認する。
- **制約**：バックアップにはアカウント情報を含めない。書き出したファイルは個人情報を含むため、利用者が適切な保管場所・BitLocker 等の環境下で管理する（[ADR-003](adr/ADR-003-data-protection.md)）。

## UC-07 バックアップから復元する

- **アクター**：担当者
- **開始条件**：ログイン済みかつ未ロックであり、誤削除、PC移行、他端末からのデータ引き継ぎ等で復元が必要である。
- **基本フロー**：
  1. 担当者が JSON バックアップファイルを選択する。
  2. アプリが形式・項目・整合性を検証する。
  3. 確認ダイアログで担当者が復元を確定する。
  4. アプリが現在のデータを自動バックアップ（`before-restore`）したうえで全件置き換え復元を実行し、復元実行者として現在のログインユーザーを記録する。
  5. アプリが復元結果を表示する。
- **例外**：検証に失敗したバックアップは復元しない。利用者が 0 件のバックアップも拒否する。
