# CareDocLib ユースケース

| 項目 | 内容 |
|---|---|
| 状態 | 初版・要件確認中 |
| 対象 | Windows Tauri デスクトップ版（現行機能および追加開発機能） |

## アクター

- **担当者**：利用者情報・共通設定を管理し、申請書を作成する。
- **管理者**：担当者と同じ申請業務に加え、担当者アカウントとバックアップを管理する。監査記録は閲覧できない。
- **監査担当者**：管理者とは別の人・アカウントで、操作記録の閲覧のみを行う。

## UC-01 アプリにログインする

- **アクター**：担当者、管理者、監査担当者
- **開始条件**：アプリを起動する。
- **基本フロー**：
  1. アプリはログイン画面を表示する。
  2. 利用者は自分のアカウント情報を入力する。
  3. アプリは認証し、利用者の操作を許可する。
  4. 30分間操作がなければアプリをロックし、再ログインを求める。
- **例外**：認証に失敗した場合はエラーを表示し、再入力を促す。失敗回数の制限は未決。

## UC-02 利用者情報を登録・更新する

- **アクター**：担当者、管理者
- **開始条件**：ログイン済みである。
- **基本フロー**：
  1. 利用者を検索・選択する。未登録の場合は新規登録する。
  2. 情報を入力または修正する。
  3. 内容を確認し、保存する。
- **結果**：保存した利用者情報を全担当者が共有する。
- **補足**：削除も可能。削除前の確認方法や誤削除時の復旧方法は未決。

## UC-03 共通設定を更新する

- **アクター**：担当者、管理者
- **開始条件**：ログイン済みである。
- **基本フロー**：
  1. 共通設定を開く。
  2. 設定値を入力・修正し、保存する。
  3. 保存した設定は以降のPDF作成に適用される。

## UC-04 申請書を作成・提出する

- **アクター**：担当者、管理者
- **開始条件**：申請依頼を受けた、認定有効期間の終了が近い、または要介護状態が変化した。
- **基本フロー**：
  1. 利用者を選ぶ。未登録の場合はUC-02で登録する。
  2. 申請に使う情報を確認し、必要があれば修正・保存する。
  3. 区分変更の場合のみ、申請理由を入力する。
  4. 申請日等を指定し、PDFを作成する。
  5. PDFをプレビューし、内容を確認する。
  6. 誤りがあれば利用者情報等を修正して再作成する。問題がなければ保存・印刷し、担当者が提出する。
- **補足**：申請のきっかけは記録・分類しない。申請区分の自動判別もしない。
- **範囲**：アプリの対象はPDFの作成・保存・印刷まで。役所への提出は担当者がアプリ外で行う。

## UC-05 担当者アカウントを管理する

- **アクター**：管理者
- **基本フロー**：
  1. 管理者が担当者アカウントを作成、停止、またはパスワード再設定する。
  2. 変更結果を確認する。
- **監査**：この操作を監査記録に残す。
- **未決**：管理者自身の復旧方法、アカウント作成・再設定時の本人確認方法。

## UC-06 バックアップを作成する

- **アクター**：管理者
- **基本フロー**：
  1. 管理者が手動バックアップを開始する。
  2. アプリがデータを暗号化し、組織管理のUSBへ保存する。
  3. 完了結果を確認する。
- **制約**：復旧キーはUSBと別に保管し、過去12か月分を保持する。
- **未決**：実施頻度、媒体の管理者、復元テストの頻度。
- **監査**：バックアップ作成・復元の操作も監査記録に残す。

## UC-07 バックアップから復元する

- **アクター**：管理者
- **開始条件**：誤削除、データ破損、端末交換等で復元が必要である。
- **基本フロー**：
  1. 管理者がUSB上のバックアップを選択する。
  2. アプリが完全性を検証し、対象を表示する。
  3. 管理者が内容を確認して復元を確定する。
  4. アプリが復元結果を表示する。
- **例外**：検証に失敗したバックアップは復元しない。

## UC-08 操作記録を確認する

- **アクター**：監査担当者
- **基本フロー**：
  1. 指名された監査担当者が操作記録を開く。
  2. 担当者・管理者の操作について、日時、対象、操作、結果を確認する。
  3. 変更時は変更項目名を確認する。個人情報の値は記録・表示しない。
- **制約**：監査担当者は記録閲覧のみを行い、記録は5年間保持する。管理者と監査担当者は別アカウントとする。
- **記録対象**：担当者の操作に加え、アカウント管理・バックアップ・復元などの管理者操作も記録する。
- **保護**：アプリ上の通常権限では記録を変更・削除できず、改ざんを検知できること。
- **運用**：組織の責任者が監査担当者を任命し、アプリ外の手順で監査専用アカウントを設定する。
- **未決**：監査担当者の認証方法、記録の検索・出力方法。

## 未決事項

- 認証失敗時の制限、管理者自身のアカウント復旧。
- 利用者情報の削除確認と誤削除からの復旧。
- バックアップの実施頻度、復元テスト、媒体・復旧キーの管理手順。
- 監査記録の検索・出力方法。
