# CareDocLib 機能要件定義書

| 項目 | 内容 |
|---|---|
| 状態 | 改訂版（ADR-002 / ADR-003 / ADR-004 反映） |
| 対象 | Windows Tauri デスクトップ版 |
| 利用者 | 担当者（1ロール共通権限） |

## 1. 目的・前提

介護認定申請の利用者情報を管理し、申請書PDFを作成する。現行機能と今後追加する認証・認可・操作者識別機能を区別する。

- サーバーを持たず、オフライン・クライアント完結で利用する（[ADR-002](adr/ADR-002-indexeddb-storage.md)）。
- 利用者データは端末内の IndexedDB に保存し、外部サーバーへ送信しない。
- 保存データの暗号化はアプリ独自では行わず、Windows ログイン＋BitLocker 等の OS 機能に委ねる（[ADR-003](adr/ADR-003-data-protection.md)）。
- 認証・認可の目的は、離席や複数担当者での共用時における **誤操作・なりすまし防止** と **操作者の識別** とする（[ADR-004](adr/ADR-004-authentication-authorization.md)）。

## 2. 現行機能（実装済）

| ID | 機能 |
|---|---|
| CUR-01 | 管理画面で利用者情報を登録・編集・削除する。 |
| CUR-02 | 共通設定を 1 件保存し、PDF 作成時に適用する。 |
| CUR-03 | 利用者、申請日、変更理由を指定して申請書 PDF を生成・プレビュー・保存する。 |
| CUR-04 | 利用者情報と共通設定を端末内の IndexedDB に保存する。 |
| CUR-05 | 利用者データが空の場合、初回起動時に初期データを投入する。 |
| CUR-06 | 利用者情報と共通設定を JSON 形式で書き出し、形式検証および復元前自動バックアップ付きで復元する（[08-backup.md](impl/08-backup.md)）。 |

## 3. 認証・認可・操作者識別機能（実装済）

### 3.1 アカウント管理・認証・認可

| ID | 利用者 | 機能・受け入れ条件 |
|---|---|---|
| FR-01 | 担当者 | アカウントが 0 件の初回起動時、最初のアカウントを登録できる。 |
| FR-02 | 担当者 | オフラインで自分のアカウントID・4桁の数字 PIN を用いてログイン・ログアウトできる。連続 5 回失敗による 1 時間の一時ロック中はログインできない。 |
| FR-03 | システム | ロールは 1 ロール（担当者共通権限）とし、未ログイン・ロック中状態では業務画面表示、データ読み書き、PDF 生成、バックアップ、アカウント管理のすべてを拒否する。 |
| FR-04 | 担当者 | 15 分間操作がない場合に自動で画面ロックされ、現在のログインユーザーの PIN 再入力で操作を再開できる（別ユーザーへの切替はログアウト経由で行う）。 |
| FR-05 | 担当者 | ログイン後、アカウントの作成、表示名変更、PIN 変更・再設定、削除ができる。最後の 1 件を削除する場合は現在の PIN 再入力を必須とし、削除後は初回登録画面に戻る。 |

### 3.2 操作者識別

| ID | 利用者 | 機能・受け入れ条件 |
|---|---|---|
| FR-06 | システム | 画面ヘッダーにログイン中の担当者名を表示する。また、利用者データおよび共通設定の作成・更新・復元時に、操作したアカウントID・表示名・日時（`createdBy` / `updatedBy` 等）を記録し、画面上で識別できるようにする。 |

### 3.3 データ保護・バックアップ互換

| ID | 利用者 | 機能・受け入れ条件 |
|---|---|---|
| FR-07 | システム | 4桁の数字 PIN は平文で保存せず、ソルト付きハッシュ（Web Crypto API による PBKDF2-SHA256 等）として IndexedDB に保存する。 |
| FR-08 | システム | `caredoc-backup` v1 形式での書き出し時にはアカウント情報および更新者メタデータを含めず、既存バックアップ仕様との互換性を維持する。 |

## 4. 制約・設計上の割り切り

- 同一 Windows アカウントを複数人で使う場合、アプリ内の JS + IndexedDB 認証だけでは DevTools やストレージファイル直接参照からの改ざん・分離までは防げない。端末のアクセス制御やドライブ暗号化は OS 側対策（Windows ログイン・BitLocker）に委ねる。
- 独立した操作履歴（監査ログ）ストアおよび改ざん検知・5年保持は今回の対象外とし、必要になった場合の将来拡張とする。
- 既存の `seedIfEmpty()` は認証・初回セットアップ完了後に実行するよう調整し、未ログイン状態で個人情報が表示・操作されないようにする。
- 品質・セキュリティ要件は [品質要件定義書](quality-requirements.md)、実装仕様は [09-auth.md](impl/09-auth.md) に記載する。
