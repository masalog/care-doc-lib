# CareDocLib 機能要件定義書

| 項目 | 内容 |
|---|---|
| 状態 | 初版・要件確認中 |
| 対象 | Windows Tauri デスクトップ版 |
| 利用者 | 担当者、管理者、監査担当者 |

## 1. 目的・前提

介護認定申請の利用者情報を管理し、申請書PDFを作成する。現行機能と今後追加する機能を区別する。追加機能は未実装である。

- 複数担当者が端末を共有し、オフラインで利用する。
- 利用者データは担当者間で共有し、外部サーバーへ送信しない。

## 2. 現行機能

| ID | 機能 |
|---|---|
| CUR-01 | 管理画面で利用者情報を登録・編集・削除する。 |
| CUR-02 | 共通設定を1件保存し、PDF作成時に適用する。 |
| CUR-03 | 利用者、申請日、変更理由を指定して申請書PDFを生成・プレビューする。 |
| CUR-04 | 利用者情報と共通設定を端末内のIndexedDBに保存する。 |
| CUR-05 | 利用者データが空の場合、初回起動時に初期データを投入する。 |

## 3. 追加開発する機能（未実装）

### 3.1 アカウント管理

| ID | 利用者 | 機能・受け入れ条件 |
|---|---|---|
| FR-01 | 担当者 | オフラインで自分のアカウントにログイン・ログアウトできる。 |
| FR-02 | 担当者 | ログイン後、全利用者データを閲覧・登録・変更・削除し、申請書PDFを作成できる。担当者間でデータ操作権限の差は設けない。 |
| FR-03 | 管理者 | 担当者アカウントを作成・停止し、パスワードを再設定できる。利用者データに対する権限は担当者と同じ。監査記録は閲覧できない。 |
| FR-04 | 担当者 | 30分間操作がない場合に自動ロックされ、再ログイン後に操作を再開できる。 |

### 3.2 操作記録

| ID | 利用者 | 機能・受け入れ条件 |
|---|---|---|
| FR-05 | システム | ログイン、利用者データの閲覧・作成・変更・削除、およびアカウント管理・バックアップ・復元などの管理者操作を記録する。 |
| FR-06 | 監査担当者 | 組織が任命し、管理者とは別に設定した監査専用アカウントで記録を閲覧できる。記録には担当者、日時、対象、操作、結果、変更項目名を含め、個人情報の値は含めない。記録は5年間保持する。 |
| FR-07 | システム | アプリ上の通常権限では監査記録を変更・削除できず、改ざんを検知できる。監査担当者にも変更・削除権限を与えない。 |

### 3.3 データ保護・バックアップ

| ID | 利用者 | 機能・受け入れ条件 |
|---|---|---|
| FR-08 | システム | 端末内に保存する利用者データを暗号化し、認証後のアプリから利用できる。 |
| FR-09 | 管理者 | 手動で暗号化バックアップを作成し、組織管理のUSB媒体へ保存できる。 |
| FR-10 | 管理者 | バックアップの完全性を検証し、正常なバックアップからデータを復元できる。 |
| FR-11 | 管理者 | 復旧キーをバックアップ媒体と別に管理し、過去12か月分のバックアップを保持できる。 |

暗号鍵・復旧キーの管理方法は設計時に定める。ハッシュ化は改ざん検知に利用できるが、秘匿と復元には暗号化が必要である。

## 4. 制約・未決事項

- 同じWindowsアカウントを複数人で使う場合、アプリのログインだけではOS上のデータアクセスを担当者ごとに分離できない。
- 管理者アカウントの復旧、パスワード要件、鍵の復旧、バックアップの実施頻度・復元テスト、USB媒体の管理者は未決。
- 現行の初期データ投入方法は、担当者アカウント導入後の取扱いと整合させる。
- 品質・セキュリティ要件は品質要件定義書に記載する。
