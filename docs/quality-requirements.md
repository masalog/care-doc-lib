# CareDocLib 品質要件定義書

| 項目 | 内容 |
|---|---|
| 状態 | 改訂版（ADR-002 / ADR-003 / ADR-004 反映） |
| 対象 | Windows Tauri デスクトップ版 |

## 本書の位置づけ

本書では、機能の実現方法ではなく、セキュリティ、信頼性、使いやすさ等の品質条件と確認方法を定める。

## 品質要件

| ID | 品質 | 要件・確認基準 |
|---|---|---|
| NFR-01 | 資格情報保護 | アカウントの 4 桁 PIN を平文で保存（IndexedDB・`sessionStorage`・ログ等）しないこと。ランダムソルト付き PBKDF2 等でハッシュ化して保管し、連続失敗ロックアウト（5回失敗で1時間制限）と単純PIN禁止が機能することを確認する。 |
| NFR-02 | 認可・セッション制御 | 画面上の非表示だけでなく、データ操作・PDF 生成・バックアップの入口でも認証済み・未ロック状態を検証すること。15 分無操作およびスリープ復帰後に自動ロックされ、最後のアカウント削除時には現在の PIN 再入力が必須となることを確認する。 |
| NFR-03 | 端末保護境界 | アプリ独自のデータ暗号化は行わず、Windows ログインパスワード・BitLocker 等の OS 標準機能で保護する前提を運用上明示すること。また、エラー表示やログに氏名・住所・被保険者番号等の個人情報や PIN を出力しないこと。 |
| NFR-04 | 完全性・互換性 | JSON バックアップの形式・型検証を維持し、破損データや不正形式から復元しないこと。認証・操作者メタデータ追加後も `caredoc-backup` v1 の書き出し・復元互換性が保たれることを確認する。 |
| NFR-05 | 復旧性 | 復元前に自動バックアップを作成し、検証・復元失敗時に元データを不整合な状態にしないこと。既存の IndexedDB（v1）データを v2 移行時に失わないことを確認する。 |
| NFR-06 | プライバシー | 業務データ・認証情報を外部送信しないこと。CSP（`tauri.conf.json`）および Tauri 権限（`capabilities/default.json`）の最小権限を維持し、オフラインで全業務を完了できることを確認する。 |
| NFR-07 | 操作性 | 画面・エラー通知は日本語とし、処理中・完了・失敗を利用者が判別できること。15 分自動ロック解除時に、入力中のフォーム内容を可能な範囲で維持できることを確認する。 |
| NFR-08 | 互換性 | 対象の Windows 環境（`bunx tauri dev` / `bunx tauri build`）で起動、認証、利用者データの読書き、PDF 生成、日本語表示、バックアップが動作し、DevTools に CSP 違反が出ないことを確認する。 |
| NFR-09 | 性能 | 数百〜数千件規模のデータ保存・一覧表示・PDF 生成が実用的な応答時間で行えること（目標値の定量化は [README](../README.md) ロードマップの「データ件数増加時の性能確認」で測定する）。 |

## 確認・運用上の留意事項

- 同一 Windows アカウントを複数人で共有する場合、アプリ認証だけでは OS 上のストレージファイル直接アクセスや DevTools 操作を完全には分離できない。
- バックアップファイルの保管場所、定期バックアップの頻度、PC 共有時の PIN 管理ルールは事業所側の運用手順として定める。
