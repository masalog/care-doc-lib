# CareDocLib 品質要件定義書

| 項目 | 内容 |
|---|---|
| 状態 | 初版・要件確認中 |
| 対象 | Windows Tauri デスクトップ版（追加開発対象） |

## 本書の位置づけ

本書では、機能の実現方法ではなく、セキュリティ、信頼性、使いやすさ等の品質条件と確認方法を定める。

## 品質要件

| ID | 品質 | 要件・確認基準 |
|---|---|---|
| NFR-01 | 機密性 | 保存データや一時ファイル、ログに、暗号化対象の個人情報が意図せず平文で残らないこと。実行中は認証済み担当者が利用できる。保存領域・ログ・一時ファイルを確認する。 |
| NFR-02 | 鍵管理 | 暗号鍵を暗号化データやバックアップと同じ場所だけに保管しないこと。パスワード再設定・管理者交代後も、定めた手順でデータを復旧できること。復旧テストで確認する。 |
| NFR-03 | 完全性 | バックアップの破損・改ざんを検知し、検証に失敗したデータを正常なものとして復元しないこと。破損データで確認する。 |
| NFR-04 | 復旧性 | バックアップからデータを復元でき、復元失敗時に元データを不整合な状態にしないこと。定期的な復元テストで確認する。頻度は運用決定が必要。 |
| NFR-05 | 監査性 | アプリ上の通常権限では監査記録を変更・削除できず、改ざんを検知できること。管理者・監査担当者それぞれの権限で確認する。 |
| NFR-06 | プライバシー | 業務データを外部送信しないこと。ネットワーク通信を確認し、オフラインでも主要業務を完了できること。 |
| NFR-07 | 操作性 | 画面・エラー通知は日本語とし、処理中・完了・失敗を利用者が判別できること。主要操作と失敗時の表示を確認する。 |
| NFR-08 | 互換性 | 対象のWindows環境でインストール、起動、更新、アンインストールができること。対応Windowsバージョンは確定後に検証する。 |
| NFR-09 | 性能 | 起動時間、PDF生成時間、最大データ件数の目標値は未設定。受け入れ試験前に実測条件と合格値を合意する。 |

## 未決事項

- 対応Windowsバージョンと最低動作環境。
- 起動・PDF生成時間、データ件数の合格目標。
- 暗号鍵の保管・復旧、管理者交代時の引き継ぎ手順。
- 監査担当者の任命・アカウント設定手順。
- 復元テストの頻度と担当者。
- 同一Windowsアカウント共有時の端末保護策。アプリ認証だけではOS上のデータアクセスを分離できない。
