## ADR-002: 端末内データ保存にIndexedDBを採用する

- **状態**：承認
- **決定日**：2026-11-27
- **対象**：Windows Tauri デスクトップアプリ

### 背景

現行アプリは利用者情報と共通設定を IndexedDB に保存している。

CareDocLib は以下を前提としたアプリケーションである。

- 単一利用者環境
- オフライン利用
- サーバーなし
- PDF生成が主目的
- 数百〜数千件規模のデータ保存

将来的な拡張として担当者アカウント、監査記録、バックアップ機能等を検討しているが、現時点ではデータ量および利用形態を考慮すると SQLite 導入の必要性は高くない。

アプリケーションの複雑化を避け、保守性を優先した永続化方式を決定する必要がある。

### 選択肢の比較

| 選択肢 | メリット | デメリット・留意点 |
|----------|----------|----------|
| IndexedDBを継続利用 | 現行実装を活用できる。追加開発が不要。Web技術のみで完結する。数千件規模のデータ保存に対応できる。 | アプリデータ領域の保護やバックアップ運用は別途考慮が必要。 |
| SQLiteを採用 | トランザクションやSQLを利用できる。DBファイルとして管理しやすい。 | Rust実装、スキーマ管理、移行処理、SQL保守が必要になる。アプリ構成が複雑化する。 |

### 決定

端末内データ保存方式として IndexedDB を継続採用する。

SQLiteへの移行は実施しない。

CareDocLib の永続化ストアは IndexedDB を正式採用とし、バックアップおよび復元は JSON エクスポート／インポートで対応する。

### 理由

- 現在の利用形態では IndexedDB の性能で十分対応可能である。
- 数百〜数千件規模のデータ保存に対して実績がある。
- 既存実装を継続利用できる。
- SQL、スキーマ管理、マイグレーション管理が不要になる。
- Rustへの依存を最小限にできる。
- JavaScript中心のアーキテクチャを維持できる。
- Web版とTauri版でコード共有しやすい。

### 影響・留意点

- IndexedDBを正式な永続化ストアとして運用する。
- データ保護はJSONバックアップ機能で対応する。
- データ増加時の性能確認を継続して行う。
- IndexedDBアクセスはRepository層を経由し、永続化処理を集約する。
- Rustはデータ管理を担当せず、Tauriランタイムおよびネイティブ機能提供に限定する。

### 結果として採用する構成

```text
JavaScript
 ├─ View
 ├─ Controller
 ├─ Validation
 ├─ Service
 ├─ Repository
 ├─ IndexedDB
 ├─ Backup
 └─ PDF

Tauri
 └─ Runtime

Rust
 └─ Tauri実行基盤
```
