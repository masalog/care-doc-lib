# ADR-001: Windowsデスクトップ基盤にTauriを採用する

- **状態**：承認
- **決定日**：2026-11-03
- **対象**：現行および今後のWindowsデスクトップ版

## 背景

CareDocLibは既存のHTML/CSS/JavaScriptによる申請書作成機能を持つ。オフラインで利用できるWindowsデスクトップアプリとして配布する方針である。

## 選択肢の比較

| 選択肢 | メリット | デメリット・留意点 |
|---|---|---|
| ブラウザー | 既存のHTML/CSS/JavaScriptをそのまま活用でき、配布が簡単。 | デスクトップアプリとして配布するには別の仕組みが必要。オフライン利用にはキャッシュ等の設計が必要。 |
| PWA | Web資産を活用でき、インストール可能。Service Worker等でオフライン対応も可能。 | オフライン動作や端末機能は個別実装が必要。ブラウザーの仕様・制限に依存する。 |
| Electron | Web資産を活用してデスクトップアプリ化でき、実行環境をアプリに同梱できる。 | Chromium等を含むため配布サイズ・リソース使用量が大きくなりやすい。依存関係の保守が必要。 |
| Tauri | Web資産を活用し、Windowsデスクトップアプリとして配布できる。Electronより軽量にできる。 | Rust側の実装・保守が必要。OSのWebViewや追加依存関係の管理が必要。 |

比較は、既存Web資産の活用、オフライン利用、Windowsアプリとしての配布、軽量さを重視した定性的な評価であり、配布サイズ等の実測比較ではない。

## 決定

Windowsデスクトップ版のアプリ基盤としてTauriを採用し、今後も継続する。認証・暗号化などの個別機能は別途設計する。

## 理由

- 既存のHTML/CSS/JavaScript資産を活用し、Windowsデスクトップアプリとして配布できる。
- オフライン利用を維持しつつ、Electronより軽量なアプリを目指せる。

## 影響・トレードオフ

- Rust側の実装・保守が必要となる。
- 依存関係が増え、脆弱性管理の対象も増える。依存関係の更新・脆弱性確認を継続する必要がある。
- WindowsではWebView2等の実行環境との互換性を確認する必要がある。
- 基本設計ではTauriの権限境界、Rust側で担う処理、WebViewとの連携範囲を明確にする。
