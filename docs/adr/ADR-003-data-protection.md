# ADR-003: データ保護方針

- **状態**：承認
- **決定日**：2026-11-06
- **対象**：Windows Tauri デスクトップアプリ
- **関連**：ADR-001（Tauri採用）、ADR-002（IndexedDB継続採用）

## 背景

CareDocLib は介護認定申請書の作成を目的とした Windows デスクトップアプリであり、利用者の個人情報を取り扱う。

主な保存データは以下である。

- 氏名
- 生年月日
- 住所
- 被保険者番号
- 要介護度
- 共通設定情報

ADR-002 において、永続化ストアとして IndexedDB を継続利用することを決定した。

そのため、保存データの保護方法、バックアップ運用、およびアプリケーションとしてのセキュリティ方針を明確にする必要がある。

## 選択肢の比較

| 選択肢 | メリット | デメリット・留意点 |
|----------|----------|----------|
| A. アプリ独自の暗号化を行う | データファイル単体の保護を強化できる。 | 鍵管理が必要になる。鍵紛失によるデータ消失リスクがある。実装・運用が複雑化する。 |
| B. OSのセキュリティ機能を利用する | 実装が単純で運用しやすい。Windows標準機能を活用できる。 | 端末の適切な運用が前提となる。 |

## 決定

### 1. アプリ独自の暗号化は行わない

CareDocLib は保存データに対する独自暗号化機能を実装しない。

保存データの保護は Windows の標準セキュリティ機能に委ねる。

### 2. Windows のセキュリティ機能を利用する

利用環境では以下を推奨する。

- Windowsログインパスワードの設定
- BitLockerによるドライブ暗号化
- 利用者ごとのWindowsアカウント利用
- OSおよびセキュリティ更新の適用

### 3. バックアップ機能を提供する

データ保護は暗号化よりもバックアップを優先する。

バックアップは JSON 形式で提供する。

- 利用者情報
- 共通設定

をエクスポート可能とする。

復元時は既存データの自動バックアップを作成してから置き換えを実施する。

### 4. 個人情報をログ出力しない

ログおよびエラー出力には個人情報を含めない。

以下の情報はログへ出力しない。

- 氏名
- 住所
- 生年月日
- 被保険者番号
- 申請情報本文

ログにはエラー内容および技術情報のみを出力する。

## 理由

### 運用の単純さを優先する

CareDocLib は小規模事業所での利用を想定している。

アプリ独自の暗号化を導入すると、

- 鍵管理
- パスワード管理
- 復旧手順

が新たに必要となる。

結果として運用負荷が増加する。

### データ消失リスクを抑える

暗号化されたデータは鍵を失うと復旧できない。

一方で、本アプリにおいては漏えい対策だけでなく、利用者情報を失わないことも重要である。

そのため、

- Windows標準機能による保護
- 定期的なバックアップ

を優先する。

### 現実的な運用に合わせる

CareDocLib は

- 単一利用者環境
- オフライン利用
- 端末内完結

を前提としている。

この利用形態では、アプリ独自暗号化による効果よりも、端末の適切な管理とバックアップ運用の効果が大きいと判断した。

## 影響・留意点

- IndexedDB に保存されたデータはアプリ独自には暗号化されない。
- BitLocker の利用を推奨する。
- Windowsログインパスワードの設定を運用前提とする。
- JSONバックアップは利用者自身が適切に保管する。
- 個人情報をログへ出力しない。
- データ保護の基本方針は「暗号化よりもバックアップを優先する」とする。

## 結果

CareDocLib は以下の方針で運用する。

```text
保存
 ↓
IndexedDB

保護
 ↓
Windowsログイン
＋
BitLocker

復旧
 ↓
JSONバックアップ

監査
 ↓
個人情報をログ出力しない
```
